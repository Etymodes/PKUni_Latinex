# Pikku 微信原生小程序

本工程为个人主体 Pikku 小程序的首个待验收版本。它使用原生 WXML / WXSS / JavaScript，复用正式网站的邮箱账号和学习接口。不是网页封装，也没有把网站微信扫码 OAuth 当作小程序登录。

## 本轮范围

- 中英文界面、七种学习语言、CFGM 四色等级卡片；排除当前显示语言对应的学习语言，与网站一致。
- 小程序专用 `components/level-selector` 使用四等宽横排与固定触控高度；中文显示初／凡／高／母，英文显示 CFGM，下方展示所选等级完整名称。组件只发出等级选择事件，由页面确认偏好保存后回传选中状态。
- 从网站源码生成完整当前题库、词卡、兼容等级路由与自适应选词算法。原题号、审核标记和 `language:lemma` 统计键不变。
- 原生练习、翻译自评、错题、收藏、背词、账号与现有资源书目。
- 同一网站邮箱账号下同步练习状态、收藏、词汇统计及学习语言／等级／背词模式。注册、邮箱验证、找回密码仍通过网站完成。
- 显示语言和游客记录仅保存在本机；游客记录不会自动合入账号。网站原有剧情进度同样不属于云端同步数据。本轮未移植剧情、模拟考试、管理员和社区界面。

## 构建与导入

在仓库根目录执行 `npm ci`，随后运行 `npm run build:wechat`。构建从 `app/page.tsx` 的题库组合和既有 TS 数据中提取内容；不下载或引入额外教材。Sharp 仅在构建时把原有等级 SVG 转为 PNG。生成的 `wechat/miniprogram/data` 和 `assets` 不提交 Git。

微信开发者工具导入 **`wechat` 目录**，其 `project.config.json` 已配置用户确认的 Pikku AppID。不能把 Next.js 根目录当成小程序导入，不需要在微信工具中“构建 npm”。开发者私有配置不提交。

## 正式联网前的必要核验

在对应小程序后台的开发设置中保存以下 **request 合法域名**（认证根域名从 `miniprogram/lib/config.js` 的 `supabaseUrl` 读取）：

1. `https://pikku.qzz.io`
2. 现有 Supabase 项目的 HTTPS 根域名

2026-09-17 用户后台截图已确认两个 request 合法域名保存成功，开发工具刷新配置并编译后域名错误消失。尚未验证中国大陆真机访问。`urlCheck` 保持 `true`；不能以开发工具忽略域名校验代替正式联网验收。没有创建第二套用户库或数据库。

依据：[微信官方工程配置示例](https://github.com/wechat-miniprogram/miniprogram-demo/blob/master/project.config.json)、[腾讯官方服务器域名配置说明](https://github.com/tencentyun/MLVBSDK/blob/master/WXMini/README.md)、[Supabase 邮箱密码认证](https://supabase.com/docs/guides/auth/passwords)。本轮未能直接读取微信官方当前 ICP 细则，不据此宣称现有域名已符合发布要求。

`config.js` 只有公开客户端配置，不含 AppSecret 或服务端密钥。Supabase 令牌用于调用网站 Worker；服务端仍使用认证得到的 UUID 作为账户键。退出清除本机登录凭据，不清除网站记录。

## 同步与故障行为

登录账号的写入经网站确认后更新统计，网络失败显示未确认提示；不后台重放词汇累加请求。游客可离线练习。刷新、重新进入小程序会读取云端记录。登录和退出后丢弃上一账号的数据响应。

收藏保存前先读取最新云端列表，只替换所选语言的收藏，以免覆盖其他语言。现有接口是按语言整组替换，没有版本锁；同一语言跨设备恰好同时写入仍可能由最后一次请求覆盖，和现有网站接口能力一致。

网站管理员覆盖题目后，刷新会应用修改与删除并清空正在进行的旧题队列。题库源码新增内容则需要重新构建、上传小程序版本。
