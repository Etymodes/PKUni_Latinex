## 1. 项目定位

哔丘 Pikku 是一个面向多语言学习、复习和考试模拟的网页平台。

项目不再只服务于北京大学拉丁语水平考试，但继续完整保留原有拉丁语功能、题库、资料体系和“比丘拟”概念。第一版支持：

- 拉丁语模式：比丘拟 · PKUni Latinex
- 日语模式：JLPT N4、N3、N2、N1
- 西班牙语模式：CEFR A1、A2、B1、B2、C1、C2

下一代平台方向已经确定：

- 网站界面支持中文／English 自主切换；
- 学习语言使用可搜索、可扩展的下拉选择；
- 增加一个 `grc` 古希腊语入口：以古典为主、阿提卡为教学骨架，同时纳入 Ionic、Aeolic、Doric、Homeric 等古典文学方言；
- 为罗曼—拉丁、日耳曼、闪米特、突厥、南岛、班图语言群和汉字词跨语言联合学习预留关系模型。
- 第一个联合学习试验确定为拉丁语—西班牙语；界面方向确定为“学习台＋可选探索地图”。
- 建立两层固定角色：四位当代用户圈朋友，以及每种学习语言一男一女的双引导角色。

核心原则：

1. 一个 Pikku 账号学习多种语言。
2. 每种语言拥有自己的等级、题型、词汇统计和考试模式。
3. 登录、进度、收藏、错题、管理后台和基础界面共用。
4. 拉丁语现有功能不降级、不丢失、不一次性重写。
5. 先实现能使用、能测试、能部署的最小多语言版本，再逐步扩充内容。

## 4. 最小多语言架构

### 4.1 不进行的改造

第一版不做：

- 不换前端框架
- 不新建第二个仓库
- 不引入额外状态管理库
- 不建立微服务
- 不建立独立图数据库
- 不建立复杂插件系统
- 不为了多语言重写现有拉丁语页面

### 4.2 语言代码

```ts
type LanguageCode = "la" | "ja" | "es";
```

### 4.3 语言配置

采用一张配置表驱动模式切换：

```ts
type LanguageConfig = {
  code: LanguageCode;
  name: string;
  nativeName: string;
  levels: string[];
  defaultLevel: string;
};
```

首批配置：

```ts
const languages = {
  la: {
    name: "拉丁语",
    nativeName: "Latīna",
    levels: ["elementary", "intermediate", "mixed", "advanced"],
  },
  ja: {
    name: "日语",
    nativeName: "日本語",
    levels: ["N4", "N3", "N2", "N1"],
  },
  es: {
    name: "西班牙语",
    nativeName: "Español",
    levels: ["A1", "A2", "B1", "B2", "C1", "C2"],
  },
};
```

### 4.4 题目最小扩展字段

在现有题目结构上增加：

```ts
language: "la" | "ja" | "es";
level: string;
skills?: string[];
source?: string;
sourceStatus?: "original" | "adapted" | "public-domain" | "licensed";
```

兼容规则：

- 旧题目没有 `language` 时一律按 `la` 处理。
- 原有拉丁语难度字段继续可用。
- 不一次性迁移全部旧数据。
- 新题目必须显式写入语言和等级。

### 4.5 学习记录

错题、收藏和进度至少按以下键区分：

```text
user_id + language + question_id
```

词汇统计至少按以下键区分：

```text
user_id + language + lemma
```

这样可避免不同语言的题目、词汇和等级互相污染。

### 4.6 下一代语言维度（规划，尚未实现）

当前 `LanguageCode = "la" | "ja" | "es"` 只描述已运行的三种学习语言，不再承担界面语言或课程轨道含义。后续必须分开：

```ts
type UiLocale = "zh-CN" | "en";
type TargetLanguage = string; // 由语言注册表校验
type CourseTrack = string; // 由课程轨道注册表校验
type ContentLocale = UiLocale; // 内部内容标签；首期由 UiLocale 直接决定
```

- `UiLocale`：导航、按钮和系统提示。
- `TargetLanguage`：当前学习语言。
- `CourseTrack`：考试、教材、阅读或语言变体轨道。
- `ContentLocale`：题干说明、提示和解析的语言标签。首期不作为独立用户设置：中文界面默认中文说明，English 界面默认 English 说明。
- 内容缺少当前界面语言版本时，必须明确显示回退语言及审核状态；不能把机器翻译伪装成正式版本。

古希腊语使用 `grc`，与现代希腊语 `el` 分开。首发方向已经确认：使用一个古希腊语入口，以古典文本为主、阿提卡语为形态与散文骨架，同时通过方言／体裁标签纳入 Ionic、Aeolic、Doric、Homeric 等古典材料。Koine、晚期古代和拜占庭材料保留为时代或课程筛选，不与首期古典主线混成一个等级。

详细产品研究见 `docs/Pikku_Global_Language_Learning_Research_v1.md`。古希腊语方向、首个联学对象和界面形态已经确认，但仍须等待 P3／P3.1 收口后再正式排期；确认方向不等于跳过现有验收。

## 5.4 古希腊语模式（已定方向，尚未实现）

首发课程不套用 CEFR，暂按五个学习域组织：

1. 文字、读音、多调符号与 Unicode 规范化；
2. 阿提卡形态；
3. 古典句法与阿提卡散文；
4. Homeric、Ionic、Aeolic、Doric 等古典文学方言与体裁；
5. 原典阅读、校勘、译本比较与作者地图。

作者和语料像拉丁语一样按时代组织。首批时代轴为：

- 迈锡尼语料与 Linear B 匿名书吏；
- 古风时代的 Homer、Hesiod、Archilochus、Sappho、Alcaeus、Alcman 等；
- 古典时代的三大悲剧诗人、Aristophanes、Herodotus、Thucydides、Xenophon、演说家、Plato、Aristotle 和 Hippocratic Corpus；
- 希腊化时代的 Callimachus、Theocritus、Apollonius Rhodius、Polybius 等；
- 罗马帝国、晚期古代与拜占庭的延伸作者和多作者语料。

完整种子表与方言原则见 `docs/Pikku_Character_Bible_v1.md` 第 6 节。真实作者节点与虚构引导角色必须分开，并记录年代置信度、方言、体裁、作品、版本、译本与来源。

自适应背词首版规则：

- 拉丁语、日语、西班牙语都按当前等级筛词；拉丁语“混合难度”合并初级和中级。
- 不设每日训练数量上限，用户可持续点击“记得／忘了”进入下一词。
- 未见词保持较高探索权重；错误率高的词提高权重；熟词降低但不永久移除；最近四张词卡暂时降权。
- 个人设置提供“纯单词记忆”和“纯单词＋语境”两种模式；语境模式只显示一条短例句，不提前暴露释义。

- 公开资料只证明词灵 Cling 宣称“无限背单词、个性化推词、造句”；没有找到其公开源码或足以复现的算法说明。Pikku 使用自己的透明权重，不声称复制 Cling 的强化学习或“最优”算法。
