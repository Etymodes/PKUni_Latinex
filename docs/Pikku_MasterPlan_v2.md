## 1. 项目定位

哔丘 Pikku 是一个面向多语言学习、复习和考试模拟的网页平台。

项目不再只服务于北京大学拉丁语水平考试，但继续完整保留原有拉丁语功能、题库、资料体系和“比丘拟”概念。原 GitHub／Cloudflare 第一版支持拉丁语、日语、西班牙语；本轮恢复 Sites 已有的七语言入口：

- 拉丁语模式：比丘拟 · PKUni Latinex
- 日语模式与西班牙语模式，保留 JLPT／CEFR 外部标签及旧记录
- 普通话、美式英语、古希腊语、俄语：各 C/F/G/M 档当前各 1 道种子题

七语公开等级统一为 CFGM，本轮恢复代码已发布至正式域名。此前将中英显示语言与 CFGM 记为“未实现”，是遗漏独立 Sites 源码造成的错误。

本轮恢复与后续方向：

- 恢复 `zh-CN`／`en` 显示语言自主切换，独立于学习语言；不声称所有既有题干和解析已翻译；
- 恢复七语言下拉框，排除当前显示语言对应的学习语言；搜索功能仍待后续；
- 恢复 `grc` 四档种子入口；以古典为主、阿提卡为教学骨架及文学方言专题的完整课程仍待建设；
- 为罗曼—拉丁、日耳曼、闪米特、突厥、南岛、班图语言群和汉字词跨语言联合学习预留关系模型。
- 第一个联合学习试验确定为拉丁语—西班牙语；界面方向确定为“学习台＋可选探索地图”。
- 建立两层固定角色：四位当代用户圈朋友，以及每种学习语言一男一女的双引导角色。

核心原则：

1. 一个 Pikku 账号学习多种语言。
2. 七语共用 CFGM 产品分级，题型、内容、词汇统计和外部考试轨道按语言隔离。
3. 登录、进度、收藏、错题、管理后台和基础界面共用。
4. 拉丁语现有功能不降级、不丢失、不一次性重写。
5. 先实现能使用、能测试、能部署的最小多语言版本，再逐步扩充内容。

## 4. 最小多语言架构

### 4.1 不进行的改造

第一版不做：

- 不换前端框架
- 不新建第二个仓库
- 不引入额外状态管理库
- 不建立微服务
- 不建立独立图数据库
- 不建立复杂插件系统
- 不为了多语言重写现有拉丁语页面

### 4.2 语言代码

```ts
type LanguageCode = "zh-mandarin" | "en-us" | "la" | "ja" | "es" | "grc" | "ru";
type PikkuLevel = "C" | "F" | "G" | "M";
```

### 4.3 语言配置

采用一张配置表驱动模式切换：

```ts
type LanguageConfig = {
  code: LanguageCode;
  name: string;
  nativeName: string;
  levels: readonly PikkuLevel[];
  defaultLevel: PikkuLevel;
};
```

七语配置均使用 `levels: ["C", "F", "G", "M"]`、`defaultLevel: "C"`。实际 `LanguageLevel`／`StudyLevel` 类型继续包含旧等级，以读取和保留历史记录；配置入口只展示 CFGM。

### 4.4 题目最小扩展字段

在现有题目结构上增加：

```ts
language: LanguageCode;
level: string;
targetText?: string;
targetLang?: string;
skills?: string[];
source?: string;
sourceStatus?: "original" | "adapted" | "public-domain" | "licensed";
```

兼容规则：

- 旧题目没有 `language` 时一律按 `la` 处理。
- 原有拉丁语难度字段继续可用。
- 不一次性迁移全部旧数据。
- 新题目必须显式写入语言和等级。
- `normalizePikkuLevel(language, level)` 只承担旧数据路由，不声明考试分级等价；具体映射见第 5 节。

### 4.5 学习记录

错题、收藏和进度至少按以下键区分：

```text
user_id + language + question_id
```

词汇统计至少按以下键区分：

```text
user_id + language + lemma
```

这样可避免不同语言的题目、词汇和等级互相污染。

### 4.6 显示语言与学习语言（Sites 已实现，本轮恢复；课程轨道仍规划）

`LanguageCode` 只描述七种学习语言。Sites v7 已将显示语言与学习语言分开，本轮恢复其本机偏好和界面入口，并接回既有 Cloudflare 账号偏好；不得继续笼统记为未实现。

```ts
type UiLocale = "zh-CN" | "en";
type TargetLanguage = string; // 由语言注册表校验
type CourseTrack = string; // 由课程轨道注册表校验
type ContentLocale = UiLocale; // 内部内容标签；首期由 UiLocale 直接决定
```

- `UiLocale`：导航、按钮和系统提示。
- `TargetLanguage`：当前学习语言。
- `CourseTrack`：考试、教材、阅读或语言变体轨道，完整独立实现仍在规划中。
- `ContentLocale`：后续完整内容语言契约，首期不作为独立用户设置。当前恢复显示语言不意味着全部旧题、解析与来源文本已有双语版本。
- 内容缺少当前界面语言版本时，必须明确显示回退语言及审核状态；不能把机器翻译伪装成正式版本。

古希腊语使用 `grc`，与现代希腊语 `el` 分开。首发方向已经确认：使用一个古希腊语入口，以古典文本为主、阿提卡语为形态与散文骨架，同时通过方言／体裁标签纳入 Ionic、Aeolic、Doric、Homeric 等古典材料。Koine、晚期古代和拜占庭材料保留为时代或课程筛选，不与首期古典主线混成一个等级。

详细产品研究见 `docs/Pikku_Global_Language_Learning_Research_v1.md`。古希腊语完整课程、首个跨语言联学和探索地图仍需排期；本轮只恢复已有界面与种子内容，不扩大为完整规划实现。

## 5. 模式与难度域

| 旧数据语言 | 兼容路由 |
| --- | --- |
| 拉丁语 | elementary→C；intermediate→F；advanced→G；历史 mixed→C |

## 5.4 古希腊语模式（四档种子已恢复，完整课程待建设）

本轮 `grc` 在 CFGM 每档各有 1 道真实语言种子题。完整课程不套用 CEFR，后续按五个学习域组织：

1. 文字、读音、多调符号与 Unicode 规范化；
2. 阿提卡形态；
3. 古典句法与阿提卡散文；
4. Homeric、Ionic、Aeolic、Doric 等古典文学方言与体裁；
5. 原典阅读、校勘、译本比较与作者地图。

作者和语料像拉丁语一样按时代组织。首批时代轴为：

- 迈锡尼语料与 Linear B 匿名书吏；
- 古风时代的 Homer、Hesiod、Archilochus、Sappho、Alcaeus、Alcman 等；
- 古典时代的三大悲剧诗人、Aristophanes、Herodotus、Thucydides、Xenophon、演说家、Plato、Aristotle 和 Hippocratic Corpus；
- 希腊化时代的 Callimachus、Theocritus、Apollonius Rhodius、Polybius 等；
- 罗马帝国、晚期古代与拜占庭的延伸作者和多作者语料。

完整种子表与方言原则见 `docs/Pikku_Character_Bible_v1.md` 第 6 节。真实作者节点与虚构引导角色必须分开，并记录年代置信度、方言、体裁、作品、版本、译本与来源。

## 9. 内容与版权治理

### 9.1 允许

- 使用公共领域原文
- 使用公开考纲
- 使用教材目录和知识点结构
- 根据知识点编写原创题
- 对少量必要文本进行合理引用并注明来源
- 链接到合法公开资源

### 9.2 禁止

- 未授权上传完整商业教材
- 大规模复制教材练习题
- 将网上找到的疑似盗版 PDF 作为网站资源发布
- 将改写题标成官方真题
- 将未经核验的资料标成确定事实

### 9.3 素材版权分级

每个源文件和拆分输出必须标记以下一种状态：

```text
public-domain | authorized | original | personal-use-only | internal-reference | rights-unclear
```

- `public-domain`、`authorized`、`original`：核验来源、授权范围和内容完整性后，可以全文拆分；进入公开站前仍需内容审核。
- `personal-use-only`、`internal-reference`、`rights-unclear`：只能建立元数据、章节／知识点映射、数据质量报告和必要短引，不生成或上传可替代原作的全文转换件。
- 带有疑似盗版来源标识、商业教材正文、现代译注、习题答案或来源不明的扫描件默认进入 `rights-unclear` 或 `internal-reference`，不得因用户上传到 Drive 就视为授权。
- 版权状态变化必须保留核验依据和日期；不能以文件名、网站可下载或“教育用途”单独推断公开许可。

### 9.4 题目状态

建议状态：

```text
draft → reviewed → published → archived
```

题目必须记录：

- 语言
- 等级
- 技能点
- 题型
- 答案
- 解析
- 来源状态
- 审核状态
